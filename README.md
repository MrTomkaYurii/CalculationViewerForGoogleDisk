# Розрахунки: переглядач публічних папок Google Drive

Статичний сайт на **Blazor WebAssembly** (.NET 10), який показує вміст публічних папок Google Drive: дерево підпапок, файли, перегляд зображень, PDF, Word і тексту просто в браузері. Відвідувач ходить без входу й може збирати **добірки** закладок. Адміністратор входить через Google, підключає папки, пише їхні описи в Markdown і прибирає зайве в добірках.

Інтерфейс тільки українською, адаптивний: від телефона до широкого монітора, світла й темна теми.

> **Стан проєкту.** Готовий інтерфейс, а файли читаються з Google Drive (потрібен ключ API, див. [«Ключ Google API»](#ключ-google-api-щоб-читати-файли-з-drive)). Список підключених папок і описи лежать у `wwwroot/data`. Firebase (вхід адміністратора, Firestore) ще не підключений: добірки й правки адміна поки живуть у пам'яті. Що залишилось, див. розділ [«Що далі»](#що-далі).

## Архітектура

Застосунок повністю клієнтський. ASP.NET-бекенд не потрібен: сайт хоститься як статика на GitHub Pages.

```
                      GitHub Pages
                           |
                           v
                 Blazor WebAssembly (C#)
                           |
        +------------------+------------------+
        |                  |                  |
        v                  v                  v
 Firebase Auth      Firebase Firestore    Google Drive API
        |                  |                  |
        v                  v                  v
  Адміністратор      Список папок,        Файли (єдине
  (вхід через        описи, добірки       сховище файлів)
  Google)
```

- **Google Drive** єдине сховище файлів. Firebase файлів не зберігає.
- **Firestore** зберігає лише метадані: які папки підключені, їхні описи, добірки закладок.
- **Firebase Auth** потрібен лише адміністратору. Відвідувачі нічого не реєструють.
- Папки в Google Drive мають бути публічними («усі, хто має посилання»). Тоді до них можна ходити з браузера з API-ключем, без сервера й без секретів.

### Точки підміни: інтерфейс → зараз → у продакшені

Уся робота з даними схована за чотирма інтерфейсами (`src/CalculationViewer/Services/Interfaces.cs`). Інтерфейс не знає, звідки дані. Тому перехід на реальні сервіси не зачепить жодного компонента.

| Інтерфейс | Що робить | Зараз (розробка) | У продакшені |
|---|---|---|---|
| `IDriveBrowser` | Вміст папки, шлях, файли, мініатюри, перегляд | `GoogleDriveBrowser` (Drive API v3), якщо задано `GoogleApiKey`; інакше `LocalDriveBrowser` через `DevDriveServer` | Google Drive API v3 |
| `IFolderCatalog` | Підключені папки, назви, описи, порядок | `SeededFolderCatalog`: файли `wwwroot/data`, правки адміна в пам'яті | Firestore |
| `ICollectionStore` | Добірки закладок | `MemoryCollectionStore` (у пам'яті) | Firestore |
| `IAdminSession` | Вхід адміністратора | `DevAdminSession` (заглушка) | Firebase Authentication (Google) |

Реєстрація сервісів: `src/CalculationViewer/Program.cs`.

## Можливості

**Відвідувач (без входу)**
- Головна: кожна підключена папка окремим блоком з повним описом («легендою») і кнопкою «Відкрити папку». Пошук іде за назвою й за текстом опису. Опис показується лише тут, на сторінці самої папки його немає.
- Папка: дерево зліва (на вузьких екранах висувається кнопкою), шлях зі згортанням глибокої вкладеності, підпапки, файли плиткою або списком, пошук і фільтри «Зображення / Документи». Підпапки за замовчуванням показуються списком (їх буває багато), кнопками в заголовку розділу можна перемкнути на плитку; вибір зберігається під час переходів між папками.
- Плитка показує зображення цілком, без обрізання. Довгі імена обрізаються посередині, щоб було видно різницю в кінці (`…_gray.png` / `…_jet.png`).
- **Предпросмотр по наведенню:** мишка на картинці понад 1 с розкриває її на весь екран (коротша затримка спрацьовувала під час звичайної прокрутки списку). Оригінал починає підвантажуватись з 0,5 с. Коли мишку прибрати, картинка закривається.
- **Переглядач:** зум колесом і щипком, панорама, подвійний тап, свайп і стрілки між файлами, стрічка мініатюр, PDF у iframe, текст, `.docx` у браузері.
- **Скачування** файлу на комп'ютер: кнопка на кожній картці (у плитці з'являється при наведенні, у списку завжди видна). Скачується оригінал під його іменем штатним скачуванням Google (`drive.usercontent.google.com/download`) через прихований фрейм, тож сторінка не перезавантажується. Якщо Google віддав сторінку замість файлу, вона відкривається у видимій вкладці. Документи Google експортуються у Word/Excel/PowerPoint.
- Файли без перегляду (`.mat` тощо) вважаються службовими: окремий згорнутий список унизу з кнопкою завантаження.
- **Добірки:** зірочка на файлі чи папці, вибір або створення добірки, власна назва закладки. Добірки спільні для всіх відвідувачів.
- Шестерня, що крутиться, показує будь-яке завантаження: старт застосунку, списки, дерево, мініатюри, переглядач.
- Світла, темна або системна тема (зберігається в `localStorage`).

**Адміністратор** (`tomka.yuriy@gmail.com`)
- Список підключених папок: порядок, редагування, видалення зі списку (файли в Drive не змінюються).
- Форма папки: посилання, перевірка доступу, назва в застосунку, опис у Markdown з живим попереднім переглядом поруч і завантаженням `.md`.
- Перегляд усіх добірок, видалення елементів і цілих добірок, «Видалити порожні».

**Маршрути**

| Адреса | Сторінка |
|---|---|
| `/` | Список папок |
| `/folder/{id1}/{id2}/…?file={id}` | Папка; у шляху id папок від підключеної до поточної, параметр `file` відкриває переглядач |

Шлях папки живе в адресі, а не береться з Google Drive: Drive не віддає батьківську папку анонімним запитам (з API-ключем), тож збудувати шлях «вгору» неможливо. З адреси виходять хлібні крихти, дерево, посилання на глибокі папки й закладки, а від Drive потрібні лише назви папок.
| `/collections`, `/collections/{id}` | Добірки |
| `/admin`, `/admin/folders`, `/admin/folders/new`, `/admin/folders/{id}` | Адміністрування папок |
| `/admin/collections` | Адміністрування добірок |

## Запуск локально

Потрібен [.NET 10 SDK](https://dotnet.microsoft.com/download). Дані беруться з реальної папки на диску. За замовчуванням це `C:\August 2026-Results`, інший шлях передається аргументом.

Два термінали:

```bash
dotnet run --project tools/DevDriveServer -- "C:\August 2026-Results"
```

```bash
dotnet run --project src/CalculationViewer --no-launch-profile --urls http://localhost:5292
```

Відкрийте http://localhost:5292.

### Ключ Google API (щоб читати файли з Drive)

Без ключа папки з каталогу показують назву й опис, а замість файлів пояснення «Файли ще не підключено».

1. https://console.cloud.google.com → створіть проєкт.
2. **APIs & Services → Library → Google Drive API → Enable.**
3. **APIs & Services → Credentials → Create credentials → API key.** Скопіюйте ключ (починається з `AIza`).
4. У ключа натисніть **Edit** і задайте обмеження:
   - **Application restrictions → Websites**, додайте `https://tomkayurii.pp.ua/*`, `http://tomkayurii.pp.ua/*` і `http://localhost:5292/*`;
   - **API restrictions → Restrict key → Google Drive API**.
5. **На сайт:** GitHub → Settings → Secrets and variables → Actions → New repository secret, ім'я `GOOGLE_API_KEY`, значення ключ. Наступний деплой підставить його в опублікований сайт (у репозиторій ключ не потрапляє).
6. **Локально:** створіть `src/CalculationViewer/wwwroot/appsettings.Development.json` (у git не потрапляє) з `{ "GoogleApiKey": "ваш ключ" }`, збережіть і перезапустіть застосунок.

Ключ у браузері видно всім, це властивість будь-якого клієнтського сайту. Захищає його саме обмеження за адресою сайту й лише на Drive API (пункт 4).

### Як підключити папку

Поки Firestore не підключений, список папок задається файлами в `src/CalculationViewer/wwwroot/data/` (однаково локально й на GitHub Pages):

1. У `folders.json` додайте запис: `id` папки Google Drive (частина посилання після `/folders/`), `title` і `descriptionFile`.
2. Опис напишіть у Markdown у файлі поруч (наприклад `october.md`).
3. Папка в Google Drive має бути відкрита для всіх, хто має посилання.
4. Закомітьте й запуште: сайт оновиться сам.

Папки з диска (DevDriveServer) у список за замовчуванням **не входять**. Щоб побачити їх під час розробки, у `wwwroot/appsettings.json` поставте `"IncludeLocalFolders": true`.

> **Після зміни файлів у `wwwroot` (наприклад `.js`) проєкт треба зібрати заново.** Blazor звіряє хеш скриптів, підрахований під час збірки, і браузер блокує змінений файл. CSS і `.razor` цього не стосується.

### DevDriveServer

Мінімальний API на ASP.NET Core, порт `5199`, слухає лише `localhost`, CORS відкритий для розробки. Це не частина продукту: у продакшені застосунок ходить у Google Drive напряму.

| Запит | Що повертає |
|---|---|
| `GET /api/roots` | Підпапки верхнього рівня (це «підключені папки») |
| `GET /api/folder/{id}` | Прямі підпапки й файли папки |
| `GET /api/path/{id}` | Шлях від підключеної папки до потрібної |
| `GET /api/file/{id}[?download=true]` | Вміст файлу, з підтримкою Range |
| `GET /api/text/{id}` | Початок текстового файлу |
| `GET /api/resolve?q=` | Знаходить папку за шляхом (для форми адміна) |

`id` це відносний шлях у Base64Url, тому клієнт бачить непрозорий рядок, як id у Drive. Файли `desktop.ini` і приховані пропускаються. Шляхи за межі кореня відхиляються.

## Дані й інтерфейс

**Модель (`Models/Models.cs`).** `DriveFolder`, `DriveFile` (з `FileKind`: Image, Pdf, Docx, Text, Other), `DriveListing` (лише прямий вміст папки), `CatalogFolder`, `BookmarkCollection`, `CollectionItem`. Лічильників вкладеного вмісту немає свідомо: Drive API їх не віддає, тому в інтерфейсі їх теж немає.

**Завантаження зображень (`js/media-loading.js`).** Google обмежує частоту запитів з однієї адреси: на пачку з 20-30 мініатюр він відповідає HTTP 429, і частина карток лишалася порожньою (заміри: 16-20 відмов із 23). Тому мініатюри вантажить не браузер, а черга:
- картинки ставляться в чергу, коли підходять до екрана, видимі першими; працює партіями по 1-6 запитів;
- швидкість підлаштовується сама: відмова 429 = пауза для всієї черги з нарастаючим часом (1,5 с … 32 с, як радить Google) і менше паралельних запитів, успіхи повертають швидкість;
- невдалий запит не здається: повторюється до успіху, після кількох невдач бере запасну адресу; поки картинки немає, крутиться шестерня, «битої» іконки немає;
- отримана мініатюра зберігається в Cache Storage браузера (`cv-thumbs-v1`), повторний захід у папку не робить запитів до Google (кеш працює на `https` і `localhost`);
- для великих зображень (переглядач, предпросмотр по наведенню) є два незалежні канали: Drive API (`alt=media`) і CDN Google (`thumbnailLink` у великому розмірі). Якщо один відмовляє або «висить», одразу береться інший.

Мініатюри беруться з `thumbnailLink`, який Drive віддає разом зі списком папки. Для розробки: `cvThumbs.stats()` у консолі браузера показує стан черги.

**Тема.** Палітра в `Theme/CvTheme.cs`, решта в `wwwroot/css/app.css`. Кольори беруться зі змінних MudBlazor (`--mud-palette-*`), тому світла й темна теми працюють без дублювання. Власні класи мають префікс `cv-`. Брейкпоінти: телефон до 600 px, дерево постійне від 960 px.

**Українська.** Множина (`1 папка / 2 папки / 5 папок`), розміри (`2,4 МБ`) і дати рахуються в `Models/Ua.cs` без ICU: Blazor WASM за замовчуванням працює в invariant-режимі. Природне сортування (`f2` перед `f10`) в `NaturalComparer`.

## Що далі

1. ~~**Google Drive API**~~ **Готово** (`GoogleDriveBrowser`): `files.list` з API-ключем, перегляд PDF/Word/документів Google через iframe Google, мініатюри `drive.google.com/thumbnail`, текст через Range. Локальний рендер `.docx` лишається запасним варіантом.
2. **Firebase Authentication** (`IAdminSession`): вхід через Google, адмін визначається за e-mail.
3. **Firestore** (`IFolderCatalog`, `ICollectionStore`): колекції `folders` і `collections`. Правила: читання публічне; запис `folders` лише адміністратору (за верифікованим e-mail); правила для добірок ще треба узгодити (див. нижче).
4. **GitHub Pages:** автодеплой уже налаштований (див. [«Публікація»](#публікація-на-github-pages)). Залишилось додати домен `*.github.io` в Authorized domains Firebase, коли підключимо Firebase Auth.
5. **Персистентність:** зараз добірки й правки адміна живуть у пам'яті й зникають після перезавантаження.

**Відкрите питання.** Хто може змінювати спільні добірки: усі відвідувачі чи лише автор і адміністратор? Друге можливе без реєстрації через анонімний Firebase-вхід. Рішення ще не прийняте.

**Що варто знати про перший деплой на GitHub Pages.** Поки джерело даних локальне, опублікована версія покаже інтерфейс, але папок не завантажить: DevDriveServer з Pages недосяжний. Повноцінно сайт запрацює після пунктів 1–3.

## Публікація на GitHub Pages

Сайт публікується автоматично: після кожного `push` у `main` запускається `.github/workflows/deploy.yml`.

**Один раз у репозиторії:** Settings → Pages → Build and deployment → **Source: GitHub Actions**.

Адреса сайту: `https://<логін>.github.io/<репозиторій>/`. Хід збірки видно у вкладці Actions, ручний запуск там же (Run workflow).

Що робить workflow:
1. `dotnet publish -c Release` (папка `release/wwwroot`).
2. Підставляє в `index.html` `<base href="/<репозиторій>/">`: сайт живе в підпапці, без цього не завантажаться скрипти й стилі. Якщо підстановка не спрацювала, збірка падає з помилкою.
3. Копіює `index.html` у `404.html`: GitHub Pages віддає його для невідомих адрес, тож прямі посилання на кшталт `/collections` відкриваються, а маршрут обирає Blazor.
4. Додає порожній `.nojekyll`, щоб Jekyll не ігнорував папку `_framework`.
5. Завантажує результат і викликає `deploy-pages`.

**Перевірити наперед на своїй машині** можна тими самими командами: `dotnet publish`, потім підміна `base href` і будь-який статичний сервер, який віддає сайт із підпапки й використовує `404.html` для невідомих адрес.

Щоб на сайті працювали файли з Google Drive, у репозиторії має бути секрет `GOOGLE_API_KEY` (див. «Ключ Google API»). Без нього сайт відкривається, показує список папок і описи, а замість вмісту папки пояснення.
